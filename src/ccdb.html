    Access to CCDB

    Last update: 20261020-1

    In this part of O2 tutorial, you will learn the technique for accessing a histogram (or some other ROOT object) at run-time in your analysis task in O2Physics from an external ROOT file, and saving that histogram in the output file of your analysis. Typically, this way you access a histogram with efficiency corrections from an external ROOT file, use information from it during analysis, and then save that histogram in the output file of your analysis. This last part is not a trivial duplication of histograms — it is important that you can easily trace back which efficiency corrections you have used in a given analysis, and that is easiest to achieve without additional bookkeeping if you save that histogram in the output of that analysis.

    To master the technique, follow these steps below...

    1. Adding new data member in the analysis task.

    Add among data members of your analysis task in O2Physics a new TH1F histogram, named histWeights (of course, you can generalize and rename later, we now focus only on technicalities).

    2. The structure of ROOT file with efficiency corrections.

    Make locally a ROOT file, named "weights.root", which has the following internal structure (you can start developing and maintaining a dedicated ROOT macro/executable for this sake, to automate the whole procedure, as some aspects of this internal structure are mandatory):

    TList "ccdb_object"
  TList "000123456"
     histWithEfficiencyCorrections_1
     histWithEfficiencyCorrections_2 
     ... more histograms in TList named "000123456" ...
  TList "000654321"
     histWithEfficiencyCorrections_1 
     histWithEfficiencyCorrections_2 
     ... more histograms in TList named "000654321" ...
  ... more nested TLists within TList "ccdb_object" ...

    In the above example internal structure of ROOT file "weighs.root":

    • TList "ccdb_object" is the top-level list which contains all other objects in this ROOT file "weights.root" — it has to be named exactly "ccdb_object";
    • TList "000123456" is the example nested TList, which will contain all histograms with efficiency corrections for the particular run number "000123456" (the name of this TList is custom);
    • "histWithEfficiencyCorrections_1" is the first example histogram, with some specific efficiency corrections pertaining to run number "000123456" (e.g. phi-weights, the name of this histogram is custom);
    • "histWithEfficiencyCorrections_2" is the second example histogram, with some other efficiency corrections pertaining to run number "000123456" (e.g. pt-weights, the name of this histogram is custom).
    • ... and so on!

    It doesn't matter for the time being which content you will have in the above example histograms "histWithEfficiencyCorrections_*" , what matters is that now you develop the code in your O2Physics analysis task, which will access, use in the analysis at run-time, and copy that histogram from an external ROOT file, into your data member histWeights , and then save it automatically in the output file "AnalysisResults.root" of your analysis, alongside of other booked objects in the analysis task.

    3. New configurable.

    Add a new configurable to your analysis code using the following code snippet:

    Configurable<std::string> cfFileWithWeights{"cfFileWithWeights", "/home/abilandz/DatasetsO2/weights.root", "path to external ROOT file which holds all particle weights"};
    For bookkeeping sake, set the title of your data member histogram histWeights to the string stored in your configurable, namely "cfFileWithWeights".

    Then, in a JSON configuration file, you would need to have the corresponding new field when you are configuring your analysis task:

     "cfFileWithWeights": "/home/abilandz/DatasetsO2/weights.root",

    An external ROOT file "weights.root" can be in three different locations, and after this tutorial, you will master access to that external file for all three cases. An external ROOT file holding efficiency corrections can be:

    1. on your local computer — just use an absolute or relative path to it in the above JSON field

    2. in your home directory in CCDB ("Calibration and Conditions Database"). This is the default, and therefore most important, way to store efficiency corrections. To inspect the content of home directory in CCDB, one can open the following URL address in the browser

      https://alice-ccdb.cern.ch/browse/Users/a/abilandz/

      Just replace in the URL address above "a/abilandz/" with your credentials, and in that browser, a valid certificate needs to be installed. For this case, prepend a file path in the above JSON field with a string "/alice-ccdb.cern.ch/"

    3. in your home directory in AliEn. This works, but it is not allowed to use this approach later in a large-scale data analysis in Hyperloop. Therefore, use this only in a local analysis for testing purposes. For this case, prepend a file path in the above JSON field with a string "/alice/cern.ch/"

    The main point behind the above convention in the JSON config of specifying the path of an external file is that now in the analysis code it will be automatically determined from that path whether that external file is on a local compute, in CCDB, or in AliEn. Correspondingly, different code needs to be used to access that file, and that is provided with the function *_TH1F GetHistogramWithWeights(...)_**, which is introduced next.

    4. function TH1F* GetHistogramWithWeights(...)

    To fetch automatically in your analysis task in O2Physics a histogram with efficiency corrections from an external ROOT file, for any of the three cases of interest mentioned above (local, CCDB, and AliEn), consider incorporating the function _TH1F GetHistogramWithWeights(...)_* below into your analysis task. The latest version of the code can be obtained directly from O2Tutorial repository, by following this direct link. The function is implemented semi-schematically, but it's trivial to finalize yourself all the remaining details:

    5. Usage of the "ccdb" object in analysis task.

    To be able to use the "ccdb" object in your analysis task, add the following line in the preamble among other include directives:

    #include <CCDB/BasicCCDBManager.h>
    Then afterward in the code, add this line just after you have started the struct definition of your analysis task: 
    Service<ccdb::BasicCCDBManager> ccdb;

    After these additions., you call the above function _TH1F GetHistogramWithWeights(...)_* in your analysis code to initialize the data member histWeights (introduced in 1. above) as follows:

    histWeights = GetHistogramWithWeights(cfFileWithWeights, "some-run-number");

    After that, you can use at runtime information from histWeights which was initialized with information from an external ROOT file. At the end of the analysis, histWeights will be automaticaly saved in the output of your analysis alongside other data members.

    6. function TObject* GetObjectFromList(...)

    Finally, the implementation of the utility function _TObject GetObjectFromList(...)_* is below. The latest version of the code can be obtained directly from O2Tutorial repository, by following this direct link GetObjectFromList.cpp. Incorporate this function's implementation to your analysis task as well:

    File src/cpp/GetObjectFromList.cpp
    TObject* GetObjectFromList(TList* list, const char* objectName)
{
 // Last update: 20261018 

 // Get TObject pointer from TList, even if it's in some nested TList. 
 // Foreseen to be used to fetch histograms or profiles from files directly. 

 // Some ideas taken from TCollection::ls()

 // If you have added histograms directly to files (without TList's), then you can fetch them directly with
 // file->Get("hist-name").

 // Example usage: TH1D *hist = (TH1D*) GetObjectFromList("some-valid-TList-pointer","some-object-name");

 // Insanity checks:
 if (!list) {
  LOGF(fatal, "\033[1;31m%s at line %d\033[0m", __FUNCTION__, __LINE__);
 }
 if (!objectName) {
  LOGF(fatal, "\033[1;31m%s at line %d\033[0m", __FUNCTION__, __LINE__);
 }
 if (0 == list->GetEntries()) {
  return NULL;
 }

 // The object is in the current base list:
 TObject* objectFinal = list->FindObject(objectName); // the final object I am after
 if (objectFinal ) { return objectFinal; }

 // Otherwise, search for the object recursively in the nested lists:
 TObject* objectIter; // iterator object in the loop below
 TIter next(list);
 while ((objectIter = next())) // double round braces are to silence the warnings
 {
  if (TString(objectIter->ClassName()).EqualTo("TList")) {
   objectFinal = GetObjectFromList(reinterpret_cast<TList*>(objectIter), objectName);
   if (objectFinal)
    return objectFinal;
  }
 } // while(objectIter = next())

 return NULL;

} // TObject* GetObjectFromList(...)

    7. Shell utility function UploadFileToCCDB

    To upload a file in CCDB, the Bash shell utility function UploadFileToCCDB can be used. That function is implemented, alongside other O2 utility functions in O2Tutorial repository, and the latest version of the code can be obtained directly by following this direct link O2.sh.

    To use it, follow these steps:

    a) Initialize locally the O2 environment using shell function MenuO2

    b) Source the implementation of all functions: 

    $ source O2.sh # adapt the path to this file

    c) Dump the config file of function UploadFileToCCDB in the current working directory. To execute this step, you must have a valid certificate in place to access ALICE Grid (see this section TBI 20261019 finalize this part): 

    $ UploadFileToCCDB -h

    d) The config file "UploadFileToCCDB.config" have the following variables and example content:

    File src/scripts/UploadFileToCCDB.config
    # Path to the file which will be uploaded:
local File="../root/labels.root"

# Relative path to the top-level directory in CCDB where 
# file will be uploaded (relative to CCDB host below):
local RelativePath="Users/a/abilandz/test-tmp"

# CCDB host:
local Host_CCDB="alice-ccdb.cern.ch"

# Corresponding AliEn dir:
local AliEnDir_CCDB="/alice/data/CCDB/Users/a/abilandz"

# Key:
local Key="ccdb_object"

# Start timestamp of validity (set to -1 or to 0 for valid as of now):
local StartTimeStamp="-1"

# End timestamp of validity in days from start timestamp
# (set e.g. 7 for 7 days):
local EndTimeStamp="7"
    It is mandatory to replace "a/abilandz" with your user credentials in AliEn (both in variables "RelativePath" and in "AliEnDir_CCDB"), and adapt a path to the local file you want to upload (in variable "File").

    e) After the config file "UploadFileToCCDB.config" is edited, simply execute 

    $ UploadFileToCCDB UploadFileToCCDB.config

    8. CCDB challenge

    a) Prepare example histogram with efficiency corrections, and save it to the file "weights.root" (see Section 2. above).

    b) Copy over that file "weights.root" into some local dir, then to AliEn, and finally upload it to CCDB.

    c) Ideally, for all three cases, and given the above implementation, you should be able to access histogram with efficiency corrections from that file just by modifying the path in the JSON configurable "cfFileWithWeights", initialize your data member histogram histWeights with its content, and save it in the output of your analysis.

    d) The very same technique will work later in the online analysis using Hyperloop, to fetch efficiency corrections at run-time from an external file — only in that case it's mandatory to use CCDB access.
